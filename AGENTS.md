# Repository instructions

## README

Treat the README as an executable product contract: timeless, present-tense
documentation of the intended finished experience, with no roadmap language,
implementation diary, or “coming soon” caveats.

## Product scope

Skillsync is a small convenience tool. Prefer the smallest reliable and
predictable design that supports setup, joining, and file synchronization. Do
not add commands, protocol layers, APIs, storage systems, or policy machinery
for the appearance of completeness. Every feature must protect a stated
guarantee or serve the core workflow, and complete-manifest designs are
preferred at the expected small scale.

## Documentation style

State behavior and guarantees directly. Do not qualify a design choice with a
claim about its purpose when the concrete constraint is enough. Describe what
the product does instead of cataloging absent features. Use negative wording
only when it clarifies a security boundary, failure mode, or compatibility
guarantee.
